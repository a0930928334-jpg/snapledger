# ADR-002：本地优先，MVP 不联网

- 状态：已采纳
- 日期：2026-10-18

## 背景

App 处理的是个人银行流水：每一笔消费、商户、转账对象、余额。这些数据一旦泄露，后果严重且无法撤回。使用者只有一个人，主要在两台自己的设备上使用。

## 决策

1. 数据只存在设备本地的 SQLite 里，离线可以完整使用。
2. **MVP 的安卓 App 不申请 `INTERNET` 权限**；桌面端也不包含任何联网代码。
3. 两台设备之间的同步，在 MVP 阶段靠**手动导出、导入加密备份**（`.slbackup`，PBKDF2 + AES-256-GCM）。
4. 自动同步服务放到第二阶段（v2.0），届时单独写 ADR 决定是否端到端加密。

## 理由

- **可验证**：安卓 Manifest 里没有 `INTERNET` 权限，系统层面就保证了 App 无法上传数据。任何人看一眼 Manifest 就能确认，比"我们承诺不上传"可信得多。
- **攻击面最小**：没有服务器、没有账号、没有 token，就没有对应的泄露途径。
- **够用**：每两三天到一周导入一次，手动备份同步的频率完全跟得上。
- **为以后留了路**：所有表都有 `id`（UUID）、`updated_at`、`deleted_at`，备份合并和以后的同步服务用同一套"按 ID、较新的为准"规则。

## 考虑过的其他方案

| 方案 | 不选的原因 |
|---|---|
| 一开始就做云同步 | 要处理认证、服务器安全、数据加密，MVP 工作量翻倍，风险也大 |
| 接 Open Banking API 直接拉流水 | 需要受监管的第三方聚合服务，数据会经过第三方，和本原则冲突 |
| 用 Google Drive / OneDrive 自动同步数据库文件 | 要申请联网权限；同时在两台设备写同一个 SQLite 文件容易损坏 |

## 后果

- MVP 里不能有任何需要联网的功能，包括崩溃上报、统计分析、在线更新检查、App 内调用 LLM（推迟到 v2.1，见 ADR-003）。
- 新加依赖时要确认它不会自己声明 `INTERNET` 权限（合并后的 Manifest 要检查）。M5 的完成标准里有这一条。
- 两台设备之间同步需要手动操作；改错时以 `updated_at` 较新的为准。
