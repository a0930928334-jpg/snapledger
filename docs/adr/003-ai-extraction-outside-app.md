# ADR-003：AI 识别放在 App 外，App 只认导入格式 v1

- 状态：已采纳
- 日期：2026-10-18

## 背景

流水的来源是银行 App（汇丰英国）的截图。从截图里识别出交易，需要多模态大模型。可以在 App 里调用 LLM API，也可以让用户在 ChatGPT 或 Claude 里手动完成识别，再把结果导入 App。

## 决策

1. **MVP 的 AI 识别在 App 外完成**：用户把截图发给已经设置好提示词（`docs/04-ai-prompt.md`）的 ChatGPT 或 Claude 项目，复制返回的 JSON 导入 App。
2. App 和 AI 之间的唯一契约是**导入格式 v1**（`schemas/import-v1.schema.json`，见 `docs/03-data-format.md`）。App 不关心 JSON 是谁生成的。
3. **AI 只负责抄写**，去重、对账、最终分类都由 App 里确定性的规则完成；AI 给出的类型和分类只是建议。
4. v2.1 再加 App 内调用 LLM API：同一个 Schema 作为 structured output 的约束，输出格式完全相同，导入逻辑不需要改。

## 理由

- **零成本、不需要 API key**：用户已经有 ChatGPT 或 Claude 的订阅；App 里不需要保存任何密钥。
- **符合 ADR-002**：App 本身不联网。截图只发给用户自己选择的 AI 服务，并且用户可以关闭训练数据选项。
- **可替换**：格式就是接口。换一家 AI、以后在 App 内调 API，甚至手写 JSON，导入流程都一样。
- **把不可靠的部分隔离出来**：LLM 的输出可能有错。App 用 Schema 严格校验、用日终余额对账、在预览页让用户确认，错误不会悄悄进入账本。

## 考虑过的其他方案

| 方案 | 不选的原因 |
|---|---|
| MVP 就在 App 内调用 LLM API | 要联网（违反 ADR-002）、要管理 API key、按次付费 |
| 在设备上跑 OCR + 规则解析 | 银行 App 的版式会变；分组标题、截断的商户名、多行描述都很难用规则稳定解析 |
| 让 AI 直接去重、汇总 | AI 会把同一天的两笔相同消费合并掉；去重必须是确定性的 |

## 后果

- 每次导入多了"发截图、复制 JSON"两步手动操作，用"从剪贴板一键导入"和安卓分享菜单尽量减少摩擦。
- 修改导入格式时，Schema、提示词、示例和测试四处要同步修改（CLAUDE.md 第 7 条）。
- 提示词的质量直接影响体验，M0 要用真实截图实测，目标是日期、金额、方向的准确率 ≥ 98%。
