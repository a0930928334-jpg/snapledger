# ADR-013：界面设计规范（DESIGN.md，Wise 结构 + 靛蓝）

- 状态：已采纳
- 日期：2026-10-19

## 背景

阶段 A、B 的界面直接用了 Material 3 的默认配色（淡紫色），功能齐全但像模板。原定"参考 Monzo"，但没有成文的规范，每加一个页面都要重新决定颜色和间距。

社区项目 [awesome-design-md](https://github.com/VoltAgent/awesome-design-md)（MIT）收集了 84 个产品的 DESIGN.md：用 Markdown 写的设计规范，AI 写界面时可以照着做。合集里没有 Monzo。

## 决策

1. 仓库根目录放 **`DESIGN.md`**，作为界面的唯一规范；`ui/.../theme/Theme.kt` 是它的代码实现，两者同步修改。
2. 结构取自合集里的 Wise 分析：浅色底配白色 24 dp 圆角卡片、底色对比代替阴影、每屏只有一张深色"主角卡"、数字用最粗字重、按钮都是胶囊形。
3. **颜色换成靛蓝**：用户比较过 Wise、Revolut、Apple 等方案（对比样稿在 claude.ai 上），不喜欢绿色，也觉得 Revolut 的纯黑太深。最终选了"Wise 结构 + 靛蓝"。
4. 同时定义浅色和深色两套色板，跟随系统切换。深色用带蓝调的石墨灰，不用纯黑。
5. 记账特有的状态色单独定义：已对平和收入用青绿（只做状态，不做品牌色）、疑似重复用琥珀、问题行用红、跳过用中性灰。
6. 只用系统字体，不打包字体文件。层级靠字重（900 / 800 / 600 / 400）区分。

## 理由

- 规范写成文字以后，后续页面（阶段 C 的搜索、分类管理、图表）不用每次重新设计，人和 AI 都照着做，风格保持一致。
- Wise 的"大圆角白卡 + 粗数字"适合记账：要看的是几个数字和一列交易，不需要复杂的装饰。
- 靛蓝既沉稳又和"钱"相关的绿色、红色状态色区分得开，状态色不会和品牌色混淆。

## 后果

- `StatusColors`、按钮、卡片都从主题读颜色，换色只需要改 `Theme.kt` 和 `DESIGN.md`。
- 改界面时先看 `DESIGN.md`；新增组件要先补进规范，再写代码。
- 桌面端 UI 测试会生成浅色和深色两套截图（`desktopApp/build/screenshots/theme-*.png`），用来人工检查。
