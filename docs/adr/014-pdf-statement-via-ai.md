# ADR-014：允许把 PDF 对账单发给 AI，输出导入格式 v1

- 状态：已采纳（部分取代 ADR-011 决策第 5 条）
- 日期：2026-10-19

## 背景

用户希望不截图，直接把汇丰的 PDF 对账单发给 ChatGPT 或 Claude，得到同样的导入 JSON。ADR-011 原来规定"对账单永远不发给 AI"，本地解析排在 v1.1。

## 决策

1. 提示词增加"PDF statements"一节，同一份提示词同时支持截图和 PDF，**导入格式 v1 不变**。
2. 整份 PDF 算作一张截图：`screenshot` 全部为 1，`position` 跨页连续编号。这样不会触发截图间对齐和"没有重叠"的提示。
3. 跳过 `BALANCE BROUGHT/CARRIED FORWARD` 行（跨页时它们是一天中间的余额，不是日终余额）。每个日期最后一行的余额作为日终余额；期初余额记为对账单开始日前一天的余额，这样第一天也能对账。
4. 不输出本人的账号、sort code、IBAN、BIC；描述里出现的对方 sort code 和账号替换成 `[masked]`。
5. 是否上传 PDF 由用户自己决定。ADR-011 的本地解析仍然保留在 v1.1。

## 理由

- 用户要的是"尽快用上"，这个方案只改提示词，不用写 PDF 解析代码。
- 对账单是文本 PDF，AI 抄写比截图更准，也没有截图之间丢行、丢日期标题的问题。
- App 端的去重、对账、分类全部复用。

## 后果

- PDF 里的姓名、地址、完整账号会上传给 AI 服务商。使用说明（docs/04 第 3 步）写明了这一点。
- 样例 `samples/example-4-statement.json`（虚构数据）和 `ImportPipelineTest` 覆盖"期初余额作为前一天余额"的对账。
